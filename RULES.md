# REGLAS DEL PROYECTO — DIRECTRICES OBLIGATORIAS

1. PLANIFICAR Y MOSTRAR PASOS: Antes de tocar código, presentar siempre el plan: qué archivos se modificarán (rutas exactas) y qué pasos se seguirán.
2. ESPERAR VALIDACIÓN (CERO ACCIÓN SIN TU 'OK'): Queda estrictamente prohibido ejecutar cualquier cambio hasta que tú apruebes el plan explícitamente.
3. NO CODIFICAR ANTE PREGUNTAS: Si solo preguntas o pides una explicación, solo se responde en texto. Cero cambios espontáneos o suposiciones.
4. NO BORRAR LO QUE YA FUNCIONA: Al agregar o cambiar botones/opciones, se mantienen intactos los indicadores y la funcionalidad previa.
5. BACKEND PRIMERO: El orden siempre es: Base de Datos -> Endpoints/Controlador -> Frontend.
6. CERO ACCIONES DESTRUCTIVAS: Prohibido seed.js, DROP TABLE o resetear datos reales de la base de datos.
7. STACK PURO: Solo Vanilla JS, CSS nativo, Node.js y PostgreSQL. Prohibido agregar librerías o frameworks externos.
8. PROBAR O VALIDAR SOLO CUANDO LO PIDAS: No ejecutar pruebas ni scripts de compilación (build_prod.js, etc.) hasta que tú lo ordenes explícitamente.
9. PROHIBIDO GIT PUSH: Jamás hacer push a GitHub por cuenta propia; solo cuando tú digas "súbelo".
